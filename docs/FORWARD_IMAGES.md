# 合并转发图片

群友发送合并转发后立刻引用提问时，图片描述可能还未准备好；如果提前把转发缓存为纯文字，后续模型只能看到图片占位符。此功能先展开并识别转发图片，再交给既有群聊缓存和回复流程。同一条转发的并发引用会等待同一个处理任务。

## 启用

在插件配置中同时设置：

| 配置 | 值 |
| --- | --- |
| `enable_forward_message_parsing` | `true` |
| `enable_forward_image_processing` | `true`，默认关闭 |
| `enable_image_processing` | `true` |
| `image_to_text_provider_id` | 一个支持图片的已有提供商 ID |
| `image_to_text_scope` | 按需选择；希望普通转发在收到时识图，可使用 `all` |

不需要新增模型接口或填写第二份 API 密钥。识图复用既有图片提示词、图片描述缓存和 `image_to_text_timeout`。聊天模型收到的是图片描述，不是原图直传；描述可能遗漏文字或细节。

新增功能只接入群聊入口，不新增私聊转发识图。关闭开关时，合并转发保持原来的文字解析行为；不支持 OneBot 调用的适配器会跳过。普通图片的独立识图流程继续使用原有配置，其单图超时现在也覆盖下载阶段。

## 引用

优先引用原转发消息并提问。结果按完整会话标识、平台消息 ID 和识图策略隔离；不同群或不同策略不共享处理结果。内存里没有原消息时，通过 OneBot `get_msg` 确认引用的是合并转发，再递归展开。普通引用保持原内容。

不根据时间窗口或发送者猜测话题；没有引用的追问仍走原有群聊上下文。`at_only` 范围下，没有 @ 的原始转发不会提前识图，随后明确引用并 @ 时可以重新获取。获取尚未确认类型的引用最多尝试两次，每次 5 秒，失败则保留原引用，不占满整条识图预算。

普通群消息不会等待其他人的转发。转发处理模块只准备上下文，不直接发送提示消息，也不决定 Bot 是否回复。

## 资源与失败处理

- `max_images_per_message` 限制每条源转发任务尝试识别的不同图片 URL 数量；同一源消息里的多条外层转发和嵌套转发共享额度，相同 URL 只调用一次。引用多个不同源消息时，各自有独立额度。
- `forward_media_timeout` 默认 90 秒，范围 10-180 秒，限制整条任务的获取、下载和识图时间。单图仍受 `image_to_text_timeout` 限制；并发引用等待的是同一任务剩余时间，不重新计时。
- 图片失败、没有 HTTP(S) 下载地址或超过数量限制时，会写入明确的未识别标记；不会把本地文件路径当作可下载的转发图片。
- 整条任务超时时，转发被替换为未完整读取标记，不提交半成品，也不会逐张累计等待。正在读取但尚未确认类型的引用失败时，保留原引用。
- 最多保留 100 条结果或进行中的任务。完成结果保留 30 分钟；失败或不完整结果保留 5 秒后允许重新获取。容量已满且全部在处理时，不挤掉正在使用的任务。
- 取消某个等待者不会取消其他请求共享的工作；插件卸载或热重载会取消并回收仍在进行的任务。
- 结果缓存是内存缓存，重启后消失；图片描述仍使用原有持久缓存。缓存保留时间不保证平台图片地址一直有效。

识图发生在群聊概率筛选前，但会先遵循插件启用范围、图片处理范围和 @ 忽略规则。即使最终不接话，也可能调用模型；降低图片数量、缩小处理范围或关闭本功能可以减少费用。这里只解析 OneBot 结构化转发，不把 JSON 分享卡片的预览文字当作完整转发，也不解析视频、语音或文件正文。

## 开发说明

`ForwardMessageParser` 通过可选图片渲染回调展开内容，不持有提供商配置。`ForwardMediaProcessor` 负责消息级任务复用、超时和短期结果缓存。`ImageHandler.describe_image` 提供单图描述和缓存复用；`main.py` 只负责配置、处理范围和生命周期接线。
